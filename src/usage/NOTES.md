# Usage readers: approach

- Each local login is a `Subscription` (`types.ts`) of `Window`s with `usedPct`, `resetsAt` and, for manual budgets, `usdLeft` and `usdBudget`.
- Claude (`claude.ts`): `claude -p /usage --output-format stream-json --verbose` is answered locally by Claude Code 2.1.280+ with no model turn. Copied from the factory's `claude-usage.ts`: the flags (no MCP, no settings, no session file), the 2.1.280 version gate, and the parse of `usage_report.rate_limits.limits`. Unlike the factory, `weekly_scoped` meters are kept as `seven_day_<model>` with a `scope`. `headroomPct` leaves them out because they only limit that one model.
- Codex (`codex.ts`): `codex app-server` + `account/rateLimits/read` (handshake, one request, EOF, kill the process group). Copied from the factory's `codex-usage.ts` and `parseCodexRateLimits`: primary/secondary, `windowDurationMins` to window names, and `rateLimitReachedType` forcing the primary to 100%.
- Several logins: each subscription can set its own `configDir` (CLAUDE_CONFIG_DIR) or `codexHome` (CODEX_HOME) and runs the volunteer's own binary. The CLIs get an allowlisted environment (`run.ts` `CLI_ENV_ALLOW`, each variable justified there), never API keys or GitHub/cloud tokens, and run in their own process group, killed whole on timeout. I dropped the factory's sandbox, egress proxy, token leases and hub.
- Cache (`cache.ts`): taken from the factory's `UsageCache`. The attempt is recorded before the read, so a failing CLI runs at most once every 5 minutes. A failed read keeps the last good windows. Staleness (15 minutes) is the factory's `STALE_MS`. A stale reading, or an incomplete one (Claude without its weekly limit, Codex without its primary window), leaves the module with every `usedPct` null and no `usdLeft`. Writes take an O_EXCL lock and go through a unique temp file.
- Manual (`manual.ts`): a weekly or monthly reset and a budget in US dollars at API prices (`{ "usd": N }`). Spend goes into `<state>/manual-ledger.json` under the same lock, keyed by period start. Reads never write. A corrupt or invalid ledger is moved to `<file>.corrupt.<time>`, and its subscriptions read as unknown until `air usage reset-ledger`.
- Prices (`prices.ts`): the one table of API prices per model id (input, 5-minute and 1-hour cache writes, cache reads, output; long-context, fast-mode and US-inference rates where listed), each with the page it came from. A model not in it, or fast mode on a model without a fast price, has no price: its calls cost nothing and serve warns. `usd()` formats dollars everywhere.
- Spend (`spent.ts`): what a job's agent spent, in dollars at API prices, from the agent's own records. Claude Code: the session transcripts (`projects/*/<session>.jsonl` and `<session>/subagents/*.jsonl` under the config dir), each `assistant` line's `message.model` and `message.usage`, once per `message.id` (a response with several content blocks repeats its line), each call priced at its model. Claude Code's own `cost-state.totalCostUSD` is written only when a session exits, so a running or killed job has none; the table reproduces it exactly for a real Claude Code 2.1.311 session ($6.5385908). Codex: rollouts whose `session_meta.cwd` is the workspace; each increase of a session's `token_count` `info.total_token_usage` is priced at the `turn_context` model then in use, cached input at the cached rate, and `last_token_usage.input_tokens` picks long-context rates. The Codex field names come from the 0.164.0 binary's strings and the rollout format `findCodexSession` already reads; no live Codex session was available to check them against.
- `usageCommand` (`index.ts`, for `air usage`): config is `~/.config/air/subscriptions.json` (default: the `claude` and `codex` logins), state is `~/.local/state/air`. `span`/`windowTitle` follow the factory's `usage.ts`. I did not port burn rate or the hub's statuses.
- Fixtures: a real, scrubbed Claude 2.1.311 `/usage` stream; the real Codex not-logged-in reply; synthetic Codex rate-limit replies, because this machine has no Codex login. The live Claude read worked with the full environment. With the allowlisted environment it is unverified on the recording machine, a factory sandbox whose login comes from a variable outside the allowlist; a normal login (credentials under CLAUDE_CONFIG_DIR, or CLAUDE_CODE_OAUTH_TOKEN) is covered.
